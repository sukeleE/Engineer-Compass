# 工科竞赛助手 Web 应用完整方案
项目名称：**Engineer-Compass 工科竞赛导航系统**
整体定位：B/S网页端应用，可后续打包成桌面版，贴合已掌握技术栈 `Three.js+GSAP+Node.js+SQLite+DeepSeek-AI`，可复用诗境长卷项目的工程模板。

## 一、整体需求拆解
四大核心模块

1. **交互式竞赛时间轴模块**
   - 横向时间轴，按月份排布全年A类工科竞赛
   - 每个竞赛是可点击标签卡片，悬停高亮
   - 点击弹出弹窗：竞赛基础信息、备赛全流程、**树状结构技术栈**
2. **全局AI对话模块**
   - 每个页面右下角常驻AI对话框
   - 支持提问：比赛难度、需要什么硬件、组队建议、备赛资料、时间冲突解决方案
   - AI可以读取当前页面上下文，例如你点开电赛，AI默认知道你正在查询电赛
3. **参赛&智能日程规划模块**
   - 用户勾选【我要参加此竞赛】
   - 系统自动生成阶段性备赛日程、任务清单、阶段性达标要求
   - 日程可手动编辑、导出，存入个人数据库
4. **知识增长引擎：未知竞赛AI收录模块** ⭐核心扩展
   - 用户要参加的比赛可能不在数据库里
   - 用户提问 → 系统自动AI联网检索 → 结构化提炼成标准竞赛卡片 → 暂存待审核 → 入库
   - **每被问到一个库外比赛，系统就多一份知识，用的人越多，库越全**

## 二、推荐整套技术栈（最大化复用现有技术储备）

### 前端
|组件|方案|说明|
|---|---|---|
|基础框架|Vue3 + Vite|组件化开发，方便弹窗、树状控件、时间轴组件封装|
|时间轴动画|GSAP|做标签入场、弹窗弹出、时间轴拖拽平滑动画，已经熟练|
|可视化组件|ECharts-Tree / D3.js|实现树状技术栈结构图，自动渲染分层技术栈|
|3D可选升级|Three.js|后期可以把2D时间轴升级卷轴式3D时间轴（参考诗境长卷）|
|UI组件库|Element-Plus|弹窗、对话框、日历日程、复选框，快速搭建基础控件|
|样式|SCSS||

### 后端
- 服务框架：`Node.js + Express`
- 数据库：`SQLite`（轻量，不需要单独数据库服务，前期开发最省事，后期可迁移MySQL）
- AI接口：`DeepSeek API`
  - 三套提示词：通用问答、**日程规划专用Prompt**、**未知竞赛资料提炼Prompt**

### 联网搜索服务（知识收录模块必需，DeepSeek API 不带联网搜索）
|方案|做法|成本|建议|
|---|---|---|---|
|① 搜索API（推荐）|接**博查（Bocha）**或 **Tavily** 搜索 API，AI自动搜官方来源|博查有免费额度；Tavily约 $5/千次|MVP后阶段补上|
|② 用户粘贴资料|用户粘贴官方通知/链接/PDF，AI结构化提炼|免费|MVP先用这个|
|③ 爬官方站|搜到官网后抓正文交给AI|反爬风险|前期不碰|

### 文件部署
Docker容器打包，可本地部署、服务器部署

## 三、数据库详细表结构（SQLite）
一共4张核心数据表

### 表1 competition 竞赛总表
|字段|类型|说明|
|---|---|---|
|id|INTEGER PRIMARY KEY|竞赛唯一编号|
|name|TEXT|全称：全国大学生电子设计竞赛|
|short_name|TEXT|简称：电赛|
|type|TEXT|A类/B类，赛道分类：电子机器人/机械/综合/数学基础|
|start_month|INTEGER|启动月份(1-12)|
|sign_start|TEXT|报名开始日期|
|sign_end|TEXT|报名截止日期|
|province_time|TEXT|省赛时间|
|national_time|TEXT|国赛时间|
|cycle|TEXT|举办周期：每年一届 / 两年一届（奇数年）|
|difficulty|INTEGER|难度星级1-5|
|intro|TEXT|竞赛简介|
|suitable_major|TEXT|适合专业|
|**source_type**|TEXT|数据来源：official / user_added / ai_search|
|**source_url**|TEXT|信息来源链接（AI收录**必须**带，否则拒绝入库）|
|**status**|TEXT|active正式数据 / pending待审核草稿|
|**data_year**|INTEGER|信息对应的年份，隔年提示"可能过时，建议重新检索"|
|**confidence**|REAL|AI自评置信度(0-1)|
|**create_time**|DATETIME|创建时间|

> 正式库数据：source_type=official，status=active。AI/用户新增：status=pending，转正后保留原来源字段供追溯。

### 表2 competition_process 备赛流程表
>每个竞赛分阶段，用于弹窗展示
|字段|类型|说明|
|---|---|---|
|id|INTEGER|主键|
|comp_id|INTEGER|关联竞赛id|
|phase_name|TEXT|阶段名称，例：基础学习阶段、项目选题阶段、实物制作、赛前冲刺|
|phase_desc|TEXT|阶段任务详情|
|suggest_month|INTEGER|建议开始月份|
|check_standard|TEXT|本阶段达标要求|

### 表3 tech_stack 技术栈树状表（递归结构）
树状结构，支持无限层级，父节点指向自己
|字段|类型|说明|
|---|---|---|
|id|INTEGER|主键|
|comp_id|INTEGER|所属竞赛|
|parent_id|INTEGER|父节点id，根节点=0|
|node_name|TEXT|技术名称，例如：硬件开发、STM32、PCB、Altium Designer|
|node_desc|TEXT|简单说明、推荐学习工具|
|level|INTEGER|层级|

>示例电赛树状样例
```
根节点
├─硬件开发
│   ├─主控单片机
│   │   ├─STM32
│   │   └─ESP32
│   ├─电路设计
│   │   ├─模拟电路
│   │   └─PCB绘制(AD)
├─嵌入式软件
│   ├─Keil、HAL库开发
│   └─传感器驱动
└─文档报告
```

### 表4 user_schedule 用户日程表
|字段|类型|说明|
|---|---|---|
|id|INTEGER|主键|
|comp_id|INTEGER|选择参加的竞赛|
|user_id|INTEGER|用户id（简易版可以先做无登录，本地存储）|
|is_custom|BOOLEAN|是否手动修改过日程|
|plan_json|TEXT|完整备赛计划json，存储每个阶段时间、任务、达标条件|
|create_time|DATETIME|生成时间|

>简易版本第一期**可以去掉账号系统**，用户日程使用浏览器LocalStorage + SQLite双存储，降低开发工作量。

## 四、知识增长引擎：未知竞赛AI收录系统设计 ⭐

### 4.1 核心流程（检索 → 提炼 → 去重 → 暂存 → 审核 → 转正）

```
用户提问"XX比赛怎么准备"
        │
        ▼
① 查库：competition 表名称模糊匹配（LIKE + 简称匹配）
        │ 命中 → 正常返回详情
        │ 未命中
        ▼
② AI 检索资料（方案①：博查/Tavily 搜索 API；方案②：引导用户粘贴官方通知）
        │
        ▼
③ 结构化提炼：提炼Prompt → 输出标准竞赛卡片JSON（含来源URL）
        │
        ▼
④ 去重检查：名称相似度匹配，防"电赛"和"全国大学生电子设计竞赛"存两条
        │
        ▼
⑤ 写入 competition 表，status='pending'（AI收录）
        │
        ▼
⑥ 前端展示：卡片正常渲染，但标注"AI收录·待核实"+来源链接
        │
        ▼
⑦ 审核转正：管理员（学生自己）后台一键"采纳"→ status='active'，或删除
```

### 4.2 设计要点
- **AI 搜到的比赛不是直接"转正"，而是带审核状态的草稿**：防止数据库被 AI 幻觉污染
- **来源必带**：pending 数据没有 source_url 一律拒绝入库
- **时效性**：pending 卡片记录 data_year，隔年展示时提示"信息可能过时，建议重新检索"
- **去重**：入库前名称相似度匹配（Edit Distance / 收录别名表）
- **前端区分**：详情弹窗对 AI 收录卡片顶部显示"AI 收集信息，点击核实官网原文"
- **搜索方式**：方案① AI 自动搜索（需接入搜索API）；方案② 用户粘贴官方通知/链接，AI 提炼——MVP 先用②，架构不变，后续换①只换数据来源，零返工

### 4.3 新增接口
```
GET  /api/competition/search?q=xxx   -- 查库，未命中触发AI检索
POST /api/competition/               -- 手动/AI新增（status=pending）
GET  /api/competition/pending        -- 待审核列表（管理端）
POST /api/competition/:id/verify     -- 采纳转正（pending → active）
DELETE /api/competition/:id          -- 删除（拒绝收录）
```

## 五、页面结构 & 详细功能设计

### 页面1：首页-交互式竞赛时间轴页面（主页面）

#### 5.1 横向时间轴主体
1. X轴：1~12月份，从左到右排布一整年
2. 每个竞赛生成**彩色标签块**，放在对应月份的坐标位置
   - 颜色区分赛道：电子机器人=蓝色，机械=橙色，综合类=绿色，数学基础=紫色
   - 悬停效果：GSAP动画放大、阴影
   - 标签文字：竞赛简称（电赛、智能车、高教杯…）
   - 两年一届比赛额外标记文字「奇数年举办」
   - AI收录的标签加小角标「AI」，悬停提示"待核实"
3. 交互
   - 鼠标滚轮横向拖动时间轴，左右滑动浏览全年赛事
   - 顶部筛选按钮：按赛道、难度、A类/B类筛选，筛选后标签动态消失
   - **顶部搜索框**：输入竞赛名称/关键词，未命中时自动走AI收录流程

#### 5.2 竞赛详情弹窗（点击标签后弹出，居中浮窗）
弹窗分为4个Tab页
- **Tab1：竞赛基础信息**
  全称、赛制、举办周期、省赛国赛准确时间、适合专业、难度、报名费、组队人数。
  AI收录卡片顶部黄条提示："AI 收集信息，待核实" + 来源链接
- **Tab2：完整备赛流程（时间线展示）**
  分阶段可视化展示，每个阶段：任务 + **硬性达标要求**
  >举例子：电赛
  >阶段1(3-4月)：单片机基础。达标要求：独立完成STM32点灯、串口、ADC采集
  >阶段2(5-6月)：模块训练。达标要求：掌握至少3种常用传感器驱动
- **Tab3：树状技术栈可视化**
  使用ECharts树图渲染，可展开/折叠，鼠标悬浮每个技术节点显示学习工具、知识点简介
- **Tab4：参赛选择按钮**
  【加入我的备赛日程】按钮 → 后端调用DeepSeek，结合当前日期自动生成个性化备赛计划表，存入用户日程库。
  生成内容模板：
  1. 分月任务清单
  2. 每周最低学习时长参考
  3. 每个阶段必须完成的达标指标
  4. 硬件/软件采购清单建议

#### 5.3 全局AI对话框（右下角悬浮，所有页面通用）
1. 默认最小化折叠，点击展开聊天窗口
2. **上下文感知**：打开电赛弹窗时，AI提示文字自动变为：`当前查看：全国大学生电子设计竞赛，可以向我提问备赛、硬件选型、组队等问题`
3. AI可回答类型
   - 通用咨询：这个比赛含金量？大一适合参加吗？
   - 技术问题：电赛需要学习哪些模块？
   - 规划类：我同时报智能车+数模会不会冲突？
   - 生成资料：帮我写一份电赛3个月学习计划
   - **库外竞赛**："XX比赛怎么准备？"→ 未命中时自动触发AI收录流程，并回复："这个比赛还未收录，已为你检索并生成资料卡片，点击查看（待核实）"
4. 聊天记录临时保存在本地

### 页面2：我的备赛日程页
1. 日历视图：显示所有已经选择参加的比赛
2. 每个竞赛展开分阶段任务卡片：任务名称、截止时间、本阶段达标标准、进度勾选框
3. 支持手动修改任务时间、新增自定义任务
4. 导出功能：导出计划为 Markdown / Excel
5. AI快捷按钮：对此备赛计划进行优化，AI重新生成调整方案

### 页面3：知识收录管理页（管理端，功能简单，可并入设置页）
1. 待审核竞赛列表（status=pending）：显示AI提炼结果、来源URL、置信度
2. 一键【采纳转正】/【删除】/【编辑后采纳】
3. 采纳后可补充备赛流程、技术栈树（可让AI根据资料自动生成草稿再人工修改）

## 六、AI 模块详细Prompt设计

### Prompt1：自动生成备赛计划（后端调用DeepSeek）
```
你是工科竞赛规划师。
竞赛名称:{comp_name}
当前日期:{now_date}
官方比赛时间:{比赛时间}
用户基础水平:默认大二工科、掌握C语言，无项目经验（允许后续让用户自定义基础）
输出严格JSON格式，分为多个备赛阶段。
每个阶段包含：阶段名称、起止日期、详细任务清单、本阶段硬性达标要求、推荐技术学习内容。
禁止多余文字，直接返回json。
```

### Prompt2：通用问答上下文Prompt
```
你是工科竞赛助手，当前用户正在查看【{当前竞赛名称}】。
结合该比赛的赛制、时间、所需技术栈回答用户问题。
如果用户问备赛方案，尽量给出分阶段可落地任务清单。
```

### Prompt3：未知竞赛资料提炼Prompt（知识收录核心）
```
你是竞赛情报员。根据以下检索资料，提取竞赛信息。
资料内容：
{用户粘贴的官方通知 / 搜索API返回的网页摘要}

只输出JSON，字段：
name, short_name, type(A类/B类+赛道), start_month, sign_start, sign_end,
province_time, national_time, cycle, difficulty(1-5), intro, suitable_major,
source_url, confidence(0-1)
规则：
1. 资料里没有的字段必须为null，禁止编造
2. 注明信息对应年份 data_year
3. 对信息完整性自评 confidence
4. 禁止多余文字，直接返回json
```

### Prompt4：名称去重判断Prompt（可选）
```
判断两个竞赛名称是否指代同一竞赛：{a} 与 {b}
只返回 true 或 false
```

## 八、分阶段开发计划（5个里程碑，可以边做边测试）

### 阶段一：基础数据+后端（1-2周）
1. 整理全部A类工科竞赛数据，导入SQLite数据库（含新加的 source/status 字段）
2. 录入每个比赛的基础备赛流程、手动录入初始版技术栈树状数据
3. 搭建Node后端接口：竞赛增删改查、详情、AI接口封装、日程接口

### 阶段二：前端时间轴 + 弹窗模块（2-3周）
1. GSAP实现横向可拖拽时间轴，渲染全部竞赛标签
2. 筛选功能（赛道、难度）、顶部搜索框
3. 点击标签弹出详情弹窗，4个tab页面
4. ECharts树图组件，渲染技术栈树

### 阶段三：AI聊天框 + 日程系统（2周）
1. 全局悬浮AI对话框组件，页面之间可以复用
2. 实现上下文传参，AI识别当前打开的竞赛
3. 加入日程按钮，后端AI自动生成备赛方案
4. 日程页面、任务清单、进度勾选、手动编辑

### 阶段四：AI知识收录系统（1-2周）⭐
1. 实现查库未命中 → 引导用户粘贴官方通知 → /api/ai/extract 提炼 → pending入库
2. 管理端：待审核列表、采纳/删除/编辑
3. 名称去重逻辑
4. （可选）接入博查/Tavily搜索API，用户提问直接自动检索，无需粘贴
5. AI收录卡片前端标记样式（AI角标、待核实提示条、来源链接）

### 阶段五：优化、动画、可选3D升级、打包部署（1-2周）
1. 全部动画优化，GSAP过渡效果
2. 数据校验、异常处理
3. 可选升级：使用Three.js，把2D横向时间轴改成卷轴式3D时间轴，复用诗境长卷项目的3D交互框架
4. Docker打包部署
