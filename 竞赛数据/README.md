## 每条竞赛的数据结构（与数据库表映射）

```markdown
### 第6项：全国大学生电子设计竞赛      → competition.name（含排行榜序号 id 对应）
- **简称**：电赛                       → short_name
- **赛道**：电子机器人                 → type（赛道色：电子机器人=蓝/机械=橙/综合=绿/数学基础=紫）
- **周期**：…                          → cycle
- **时间线**：报名约X月｜省赛约X月｜国赛约X月 → sign_start/sign_end/province_time/national_time + start_month（时间轴用）
- **难度**：★★★★★                   → difficulty（★数）
- **适合专业**：…                      → suitable_major
- **组队**：3人/队                     → intro 或独立字段
- **简介**：…                          → intro

#### 子赛项                                  → competition_process（一个子赛项=一个阶段条目）
1. **本科组-电源类**                    
   - **赛制与规则**：…                  → phase_desc
   - **技术栈**：                        → tech_stack 树（递归表，根=该子赛项名）
     ├─ 硬件设计
     │  ├─ STM32
     │  └─ PCB设计
   - **达标建议**：…                    → check_standard
```

## 导入 SQLite 建议

1. `competition` 表：解析 `### 第X项` 块 + 键值行 → 1 行/竞赛，`source_type='official'`，`status='active'`，`data_year=2025`
2. `competition_process` 表：解析 `#### 子赛项` 列表 → 1 行/子赛项（`comp_id` 关联，`phase_name`=子赛项名，`phase_desc`=赛制与规则，`check_standard`=达标建议，`suggest_month`=取时间线中的报名月份）
3. `tech_stack` 表：解析 `技术栈` 树 → 递归行（`comp_id` 关联，根节点=子赛项名，`parent_id` 递归，`node_name`=技术名，`level`=层级，`node_desc` 留空待补）
4. 时间线里 `（时间可能逐年变动）` 的字段入库时保持原样，前端弹窗提示"以当届官方通知为准"

## 已知注意事项

1. **电赛周期**：奇数年国赛、偶数年省赛（每年都有赛事）——已按正确事实写入
2. **智能车组别**：按 2025 年第 20 届核实（10 竞速组 + AI 创意组），组别逐年微调，需关注当届公告
3. **两年一届的竞赛**：水利创新（第九届2025）、物流设计、机械创新、工程实践与创新、周培源力学（奇数年）、金相（偶数年国赛）、工业设计（偶数年）等——cycle 字段已标注
4. **更名竞赛**：第19项已并入CURC体系、第46项BIM已更名"国际高校BIM毕业设计创新大赛"、第70项已更名"全国大学生医学创新大赛"——按最新名称记录
5. 所有时间均为近年实际届次，导入后可每年由管理员/AI 收录流程刷新
6. 非工科竞赛（设计/外语/医学）无技术栈字段，用「能力与工具要求」树替代，导入时 `tech_stack` 节点可加前缀"能力:"区分
